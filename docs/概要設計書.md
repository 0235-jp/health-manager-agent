# ヘルスマネジメントエージェントシステム - 概要設計書

## システム概要

ユーザーのヘルス情報を自動・手動で収集し、定期的にリスクや傾向を評価するエージェントシステム。

---

## アーキテクチャ

```
┌─────────────────┐     ┌─────────────────────────┐     ┌─────────────────┐
│  Web Frontend   │────▶│     Node.js Server      │────▶│  External APIs  │
│  (React/Vite)   │◀────│  + Anthropic Agent SDK  │◀────│  (Oura, Huawei) │
└─────────────────┘     └─────────────────────────┘     └─────────────────┘
                                   │
                                   ▼
                             ┌──────────┐
                             │  SQLite  │
                             └──────────┘
```

**実行環境**: ローカルPC（Cloudflare Tunnel経由で外部公開予定）

## 1. Webフロントアプリ

### 1.1 ダッシュボード機能
- 収集したヘルス情報の一覧表示
- グラフによるデータ可視化（時系列トレンド）
- 分析結果・評価レポートの一覧表示

### 1.2 データ管理機能
- 手動でのデータ入力
- 既存データの変更・削除
- 手動入力項目の定義（カスタム項目追加）

### 1.3 設定機能
- **データ収集設定**
  - データ収集間隔の調整（デフォルト: 1時間）
  - 利用するプラグインの選択
  - 重複するデータソースの優先順位設定
- **カスタム指示設定**
  - 評価時に注目してほしいポイントの追加・編集・削除
  - 指示ごとの有効/無効切り替え
  - 優先度の設定
- **Webhook設定**
  - 評価レポート送信先の設定
  - 手動計測リマインダーの通知設定
- **手動計測項目の通知間隔設定**

## 2. サーバー (Node.js + Anthropic Agent SDK)

### 2.1 データ収集機能
| 種別 | 説明 |
|------|------|
| 自動収集 | プラグインを使用してヘルス情報を定期取得（デフォルト: 1時間間隔） |
| 手動入力 | Webアプリから入力されたデータを保存 |

### 2.2 データソース管理
- プラグイン間で取得データが重複する場合の調整機能
- Webフロントでどのデータソースを優先するか選択可能
- 利用可能なデータ:
  - プラグインで取得可能な項目
  - Webアプリで設定した手動入力項目

### 2.3 評価レポート機能
| レポート種別 | タイミング | 内容 |
|-------------|-----------|------|
| 取得時レポート | データ取得完了後 | 個別評価レポート |
| 日次レポート | 毎日深夜 | 前日1日分の総合評価レポート |

- レポート作成後、Webhookでデータ送信可能

### 2.4 カスタム指示機能（評価フォーカス設定）
ユーザーが評価時に特に注目してほしいポイントをカスタム指示として設定可能。

**設定例:**
- 「体重が70kgを超えないように注意してください」
- 「血圧の変動を特に気にしています」
- 「睡眠時間が6時間未満の場合は警告してください」
- 「運動量が少ない日が続いたらアドバイスをください」

**機能:**
- 複数のカスタム指示を登録可能
- 指示ごとに有効/無効を切り替え可能
- 取得時レポート・日次レポート両方に適用
- Webフロントから追加・編集・削除が可能

### 2.5 通知機能
- 手動計測に設定した項目: 設定した期間ごとにWebhookで通知
- 評価レポート完成時: Webhook通知

## 3. 統一プラグインシステム

### 3.1 概要

本システムでは3種類のプラグインを統一的に管理します：

| プラグインタイプ | 担当 | 実行タイミング |
|----------------|------|---------------|
| **DataSource** | 外部APIからのデータ収集・認証処理 | Scheduler による定期実行 |
| **Agent** | AIによるレポート生成・分析 | レポート生成時 |
| **Notification** | レポート等の通知送信 | イベント発生時 |

すべてのプラグインは同じLoader/Manager/Registryで管理され、`plugins/`フォルダに配置されます。

### 3.2 アーキテクチャ

```
                        +------------------+
                        |  PluginManager   |
                        |  (Singleton)     |
                        +--------+---------+
                                 │
                  +--------------+---------------+
                  │              │               │
        +---------▼----+ +-------▼-------+ +----▼---------+
        | PluginLoader | | PluginRegistry| |   EventBus   |
        +--------------+ +---------------+ +--------------+
                  │              │               │
        +---------▼--------------▼---------------▼---------+
        │                   Plugin Types                   │
        │  +-----------+  +-----------+  +--------------+  │
        │  |DataSource |  |   Agent   |  | Notification |  │
        │  |  Plugin   |  |   Plugin  |  |    Plugin    |  │
        │  +-----------+  +-----------+  +--------------+  │
        +--------------------------------------------------+
```

**コンポーネント責務:**
| コンポーネント | 責務 |
|--------------|------|
| **PluginLoader** | `plugins/`からプラグイン読み込み、manifest検証、動的import |
| **PluginRegistry** | プラグインインスタンス管理、状態追跡、型別アクセス |
| **PluginManager** | 統括オーケストレーション、設定UI向けAPI、ライフサイクル管理 |
| **EventBus** | Pub/Subパターンで通知イベント配信 |

### 3.3 プラグイン共通インターフェース

すべてのプラグインは共通の基底インターフェースを持ちます：

```typescript
type PluginType = 'data-source' | 'agent' | 'notification';

interface PluginManifest {
  name: string;           // 識別子（英数字-_のみ）
  displayName: string;    // 表示名
  version: string;        // セマンティックバージョン
  type: PluginType;       // プラグインタイプ
  description?: string;
  main: string;           // エントリーポイント (例: "dist/index.js")
  configSchema?: Record<string, ConfigField>;
  requiredEnvVars?: string[];
}

interface BasePlugin {
  readonly manifest: PluginManifest;
  initialize(config: Record<string, unknown>): Promise<void>;
  dispose(): Promise<void>;
  validateConfig?(config: Record<string, unknown>): Promise<ValidationResult>;
}
```

### 3.4 DataSourcePlugin（データ収集）

外部APIからヘルスデータを取得するプラグイン。ZIP形式でパッケージ化し、Webフロントからインポート可能。

**プラグイン構成:**
```
oura-plugin.zip
├── manifest.json      # プラグイン情報・設定スキーマ
├── index.js           # エントリーポイント
├── package.json       # 依存関係
└── README.md          # 使用方法
```

**manifest.json 例:**
```json
{
  "name": "oura-ring",
  "displayName": "Oura Ring",
  "version": "1.0.0",
  "description": "Oura Ring APIからデータを取得",
  "author": "your-name",
  "supportedDataTypes": ["sleep", "heart_rate", "activity", "temperature"],
  "configSchema": {
    "accessToken": { "type": "string", "label": "アクセストークン", "secret": true }
  }
}
```

**DataSourcePluginインターフェース:**
```typescript
interface DataSourceManifest extends PluginManifest {
  type: 'data-source';
  supportedDataTypes: DataTypeDefinition[];
  fetchStrategy: 'manual' | 'scheduled' | 'both';
  defaultFetchInterval?: number;
}

interface DataSourcePlugin extends BasePlugin {
  fetchData(options: FetchOptions): Promise<FetchResult>;
  testConnection(): Promise<ConnectionTestResult>;
  getAuthorizationUrl?(): Promise<string>;  // OAuth対応
  handleOAuthCallback?(code: string): Promise<void>;
}
```

**初期DataSourceプラグイン:**
| プラグイン名 | 取得可能データ | 備考 |
|-------------|--------------|------|
| oura-ring | 睡眠、心拍数、活動量、体温 | OAuth2/Personal Token |
| huawei-health | 歩数、心拍数、睡眠、運動 | API連携 |

### 3.5 AgentPlugin（AI分析）

AIを使用してレポート生成を行うプラグイン。設定画面から動的に切り替え可能。

```typescript
interface AgentManifest extends PluginManifest {
  type: 'agent';
  provider: string;       // "anthropic", "openai"等
  supportedModels?: string[];
  capabilities: AgentCapabilities;
}

interface AgentPlugin extends BasePlugin {
  readonly name: string;  // AgentAdapter互換
  generateReport(params: GenerateReportParams): Promise<ReportContent>;
  generateReportStream?(params: GenerateReportParams): AsyncGenerator<ReportChunk>;
}
```

**manifest.json例（Anthropic）:**
```json
{
  "name": "anthropic-agent",
  "displayName": "Anthropic Claude",
  "version": "1.0.0",
  "type": "agent",
  "main": "dist/index.js",
  "provider": "anthropic",
  "supportedModels": ["claude-opus-4-5-20251101", "claude-sonnet-4-20250514"],
  "capabilities": { "streaming": true, "functionCalling": true, "structuredOutput": true },
  "requiredEnvVars": ["ANTHROPIC_API_KEY"]
}
```

### 3.6 NotificationPlugin（通知）

レポート生成後などのイベントに応じて通知を送信するプラグイン。

```typescript
interface NotificationManifest extends PluginManifest {
  type: 'notification';
  supportedEvents: NotificationEventType[];
  deliveryMethod: 'push' | 'pull' | 'both';
}

type NotificationEventType =
  | 'report:generated'  // レポート生成完了
  | 'report:daily'      // 日次レポート生成
  | 'health:alert'      // 健康アラート
  | 'data:fetched';     // データ取得完了

interface NotificationPlugin extends BasePlugin {
  notify(event: NotificationEvent): Promise<NotificationResult>;
  testNotification(): Promise<NotificationResult>;
}
```

**manifest.json例（Webhook）:**
```json
{
  "name": "webhook-notification",
  "displayName": "Webhook",
  "version": "1.0.0",
  "type": "notification",
  "main": "dist/index.js",
  "supportedEvents": ["report:generated", "report:daily", "health:alert"],
  "deliveryMethod": "push",
  "configSchema": {
    "webhookUrl": { "type": "string", "label": "Webhook URL", "required": true },
    "enabledEvents": { "type": "string", "label": "有効なイベント", "default": "report:daily" }
  }
}
```

### 3.7 イベントシステム

通知プラグインはEventBusを通じてイベントを受信します：

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   Scheduler     │     │  AgentService   │     │  API Routes     │
│  (データ収集)   │     │  (レポート生成)  │     │  (手動操作)     │
└────────┬────────┘     └────────┬────────┘     └────────┬────────┘
         │                       │                       │
         │  data:fetched         │  report:daily         │  report:generated
         ▼                       ▼                       ▼
┌─────────────────────────────────────────────────────────────────┐
│                          EventBus                               │
└──────────────────────────┬──────────────────────────────────────┘
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ Webhook  │ │  Slack   │ │  Email   │
        │ Plugin   │ │  Plugin  │ │  Plugin  │
        └──────────┘ └──────────┘ └──────────┘
```

### 3.8 Skills（エージェントのデータ照会機能）

Skillsは**保存済みデータの照会・分析専用**。データ取得はプラグインが担当。
SkillsはAgent SDKの機能として、`.claude/skills/`ディレクトリに`SKILL.md`ファイルとして定義し、
Agent SDKが自動検出して利用可能にします。

| Skill名 | 説明 | 用途 |
|---------|------|------|
| `get_health_data` | ヘルスデータを照会する | 保存済みデータの検索・取得・集計 |

**Skill定義ファイル構成:**
```
.claude/
└── skills/
    └── get-health-data/
        └── SKILL.md    # スキルの説明・使用方法・実行手順を記述
```

**SKILL.md の概要:**
- スキルの説明と使用方法
- 受け付けるパラメータ（query_type, data_types, start_date, end_date）
- 実行手順（APIエンドポイントの呼び出し方法）
- 出力形式の定義

**注意:** Skillsはコード内でToolとして直接定義するのではなく、
マークダウンファイルとして記述します。Agent SDKはこれを読み込み、
エージェントへの指示として機能させます。

### 3.9 プラグイン管理機能（Webフロント）
- プラグインのインポート（ZIPアップロード）
- インストール済みプラグイン一覧（タイプ別フィルタ）
- プラグインごとの設定（認証情報入力）
- プラグインの有効/無効切り替え
- **エージェントプラグインの切り替え**（設定画面から動的に）
- 接続テスト実行
- 通知テスト送信
- プラグインの削除

### 3.10 プラグイン配布

プラグインはGitHub Releasesを通じてZIP形式で配布します。

**タグ形式:** `plugin-{name}-v{version}` (例: `plugin-webhook-notification-v1.0.0`)

**ZIP配布フロー:**
1. プラグインディレクトリでビルド (`npm run build`)
2. 配布用ZIPを作成（`manifest.json`, `dist/`, `package.json`を含む）
3. GitHub Releasesにアップロード

## 4. データモデル

### 4.1 ヘルスデータ (health_data)
```sql
CREATE TABLE health_data (
  id INTEGER PRIMARY KEY,
  data_type TEXT NOT NULL,        -- 標準タイプまたはプラグイン定義タイプ
  value REAL NOT NULL,
  unit TEXT,                      -- kg, bpm, hours など
  source TEXT NOT NULL,           -- プラグイン名 or "manual"
  recorded_at DATETIME NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**標準データタイプ（サーバー定義・推奨）:**
| カテゴリ | データタイプ | 単位 | 説明 |
|---------|-------------|------|------|
| 身体 | `weight` | kg | 体重 |
| 身体 | `height` | cm | 身長 |
| 身体 | `body_fat` | % | 体脂肪率 |
| 心臓 | `heart_rate` | bpm | 心拍数 |
| 心臓 | `heart_rate_variability` | ms | 心拍変動 |
| 心臓 | `blood_pressure_systolic` | mmHg | 収縮期血圧 |
| 心臓 | `blood_pressure_diastolic` | mmHg | 拡張期血圧 |
| 睡眠 | `sleep_duration` | hours | 睡眠時間 |
| 睡眠 | `sleep_quality` | score | 睡眠品質スコア |
| 睡眠 | `deep_sleep` | hours | 深い睡眠時間 |
| 睡眠 | `rem_sleep` | hours | レム睡眠時間 |
| 活動 | `steps` | count | 歩数 |
| 活動 | `calories_burned` | kcal | 消費カロリー |
| 活動 | `active_minutes` | minutes | アクティブ時間 |
| 体温 | `body_temperature` | °C | 体温 |
| 体温 | `skin_temperature` | °C | 皮膚温度 |
| 精神 | `stress_level` | score | ストレスレベル |
| 精神 | `mood` | score | 気分 |

**プラグイン独自タイプ:**
- プラグインは独自のデータタイプを自由に定義可能
- 命名規則: `{plugin_name}:{custom_type}` （例: `oura:readiness_score`）
- 標準タイプにマッピング可能な場合は標準タイプの使用を推奨

### 4.2 データタイプ定義 (data_types)
```sql
CREATE TABLE data_types (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,       -- データタイプ識別子
  display_name TEXT NOT NULL,      -- 表示名
  category TEXT,                   -- カテゴリ（身体、心臓、睡眠など）
  unit TEXT,                       -- 単位
  is_standard BOOLEAN DEFAULT 0,   -- 標準タイプかどうか
  plugin_name TEXT,                -- プラグイン定義の場合はプラグイン名
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
-- 標準タイプは初期データとして登録
-- プラグイン独自タイプはプラグインインストール時に自動登録
```

### 4.3 評価レポート (reports)
```sql
CREATE TABLE reports (
  id INTEGER PRIMARY KEY,
  report_type TEXT NOT NULL,      -- on_fetch, daily
  period_start DATETIME NOT NULL,
  period_end DATETIME NOT NULL,
  content TEXT NOT NULL,          -- JSON: 分析結果、リスク評価、傾向
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 4.4 設定 (settings)
```sql
CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,            -- JSON値
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
-- 保存する設定例:
-- collection_interval: 3600 (秒)
-- active_plugins: ["oura-ring", "huawei-health"]
-- data_source_priority: {"heart_rate": "oura-ring", "steps": "huawei-health"}
-- webhook_url: "https://..."
-- manual_measurement_items: ["weight", "blood_pressure"]
-- notification_intervals: {"weight": 86400, "blood_pressure": 43200}
```

### 4.5 プラグイン (plugins)
```sql
CREATE TABLE plugins (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,        -- プラグイン識別子
  display_name TEXT NOT NULL,       -- 表示名
  version TEXT NOT NULL,
  description TEXT,
  supported_data_types TEXT,        -- JSON: ["sleep", "heart_rate", ...]
  config TEXT,                      -- JSON: 設定値（認証情報など）
  is_active BOOLEAN DEFAULT 1,
  installed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 4.6 手動入力項目定義 (custom_data_types)
```sql
CREATE TABLE custom_data_types (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  unit TEXT,
  is_active BOOLEAN DEFAULT 1,
  notification_interval INTEGER,  -- 秒（0=通知なし）
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 4.7 カスタム指示 (custom_instructions)
```sql
CREATE TABLE custom_instructions (
  id INTEGER PRIMARY KEY,
  instruction TEXT NOT NULL,      -- カスタム指示内容
  priority INTEGER DEFAULT 0,     -- 優先度（高いほど重要）
  is_active BOOLEAN DEFAULT 1,    -- 有効/無効
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
-- 例:
-- "体重が70kgを超えないように注意してください"
-- "睡眠時間が6時間未満の場合は警告してください"
```

## 5. 技術スタック

| レイヤー | 技術 | 理由 |
|---------|------|------|
| Frontend | React + Vite + TypeScript | 高速開発、豊富なエコシステム |
| UIライブラリ | Tailwind CSS + shadcn/ui | モダンで美しいUI |
| チャート | Recharts | Reactとの親和性が高い |
| Backend | Node.js + TypeScript | フロントと言語統一 |
| Agent SDK | @anthropic-ai/claude-agent-sdk | AIエージェント機能 |
| Database | SQLite (better-sqlite3) | セットアップ不要、軽量 |
| API | REST API | シンプルで理解しやすい |
| スケジューラ | node-cron | 定期実行処理 |

## 7. 主要機能フロー

### 7.1 自動データ収集フロー
```
1. Scheduler (1時間ごと)
   ↓
2. Plugin Managerが有効なプラグインを順次実行
   ↓
3. 各プラグインがAPIからデータ取得
   ↓
4. 取得データをDBに保存
   ↓
5. 重複データの解決（優先順位に従う）
   ↓
6. Agent SDKで取得時評価レポート作成
   - query()関数でAgent SDKを呼び出し
   - .claude/skills/get-health-data/SKILL.md を自動検出
   - Skillの指示に従いデータ照会 + カスタム指示を考慮
   ↓
7. Webhook送信（設定されている場合）
```

### 7.2 日次レポートフロー
```
1. Scheduler (毎日深夜)
   ↓
2. 前日のデータを集計
   ↓
3. Agent SDKで日次評価レポート作成
   ↓
4. DBに保存
   ↓
5. Webhook送信
```

### 7.3 手動計測リマインダーフロー
```
1. Scheduler (設定間隔ごと)
   ↓
2. 未入力の手動計測項目をチェック
   ↓
3. Webhook通知送信
```

## 8. API エンドポイント（案）

### ヘルスデータ
- `GET /api/health-data` - データ一覧取得
- `GET /api/health-data/:id` - 個別データ取得
- `POST /api/health-data` - 手動データ追加
- `PUT /api/health-data/:id` - データ更新
- `DELETE /api/health-data/:id` - データ削除

### データタイプ（エージェント用）
- `GET /api/data-types` - 利用可能なデータタイプ一覧取得（標準 + プラグイン定義）

### レポート
- `GET /api/reports` - レポート一覧取得
- `GET /api/reports/:id` - 個別レポート取得
- `POST /api/reports/generate` - 手動レポート生成

### 設定
- `GET /api/settings` - 設定取得
- `PUT /api/settings` - 設定更新

### カスタム指示
- `GET /api/custom-instructions` - カスタム指示一覧取得
- `POST /api/custom-instructions` - カスタム指示追加
- `PUT /api/custom-instructions/:id` - カスタム指示更新
- `DELETE /api/custom-instructions/:id` - カスタム指示削除

### プラグイン
- `GET /api/plugins` - インストール済みプラグイン一覧
- `POST /api/plugins/install` - プラグインインストール（ZIPアップロード）
- `DELETE /api/plugins/:name` - プラグイン削除
- `PUT /api/plugins/:name/config` - プラグイン設定更新
- `POST /api/plugins/:name/test` - 接続テスト
- `POST /api/plugins/:name/sync` - 手動データ同期

## 9. 実装順序

> **順序設計の方針**: 技術リスクの高いAgent SDK統合を早期に検証し、問題発見時の手戻りを最小化する。プラグインシステムは確立されたパターンのためリスクが低く、後半に配置。

### Phase 1: 基盤構築
1. プロジェクト初期化（モノレポ設定）
2. SQLiteデータベースセットアップ
3. 基本的なAPIサーバー構築
4. フロントエンド骨格作成

### Phase 2: コア機能 + Agent SDK検証
5. 手動データ入力機能
6. データ一覧・グラフ表示
7. 設定画面
8. Agent SDK統合プロトタイプ（最小限のSkill + レポート生成検証）

### Phase 3: エージェント機能完成
9. `get_health_data` Skill完全実装
10. 取得時評価レポート機能
11. 日次評価レポート機能

### Phase 4: プラグインシステム実装
12. プラグインインターフェース設計
13. Plugin Manager・Loader実装
14. スケジューラ統合
15. プラグインサンドボックス（セキュリティ）

### Phase 5: 通知機能
18. Webhook送信機能
19. 手動計測リマインダー
